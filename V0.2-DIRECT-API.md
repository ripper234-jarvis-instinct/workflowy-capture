# v0.2: direct API capture (guide for developers)

v0.1 drove the Workflowy web editor from a browser. It works, but it is slow and fragile. v0.2 replaces the browser with a direct API write. This page has what you need to build it.

## 1. The create-bullet call

Workflowy exposes an endpoint that creates one bullet at a target node. This is the call Fredo uses to write captures. It is unpublished, so treat it as subject to change.

```text
POST https://beta.workflowy.com/api/bullets/create/
Content-Type: application/json
Authorization: Bearer <WORKFLOWY_API_TOKEN>
```

| Field | Type | Notes |
| --- | --- | --- |
| `new_bullet_id` | string (UUID) | Generated by the client. |
| `new_bullet_title` | string | The bullet text. |
| `new_bullet_note` | string | Optional note under the bullet. Use `""` for none. |
| `save_location_url` | string | Internal link of the target node. In Workflowy: open the node, three dots menu, "Copy internal link". |
| `position` | `"top"` or `"bottom"` | Optional. Where in the target's children the bullet lands. |

The token comes from `https://beta.workflowy.com/api-key/`.

### Reference code

This is the write code Fredo uses (TypeScript, axios). `CREATE_WF_BULLET_URL` is the endpoint above. `hashtagUrl` is the target node's internal link, `content` is the captured text, `position` is optional.

```ts
const CREATE_WF_BULLET_URL = "https://beta.workflowy.com/api/bullets/create/";

const createNewBullet: CreateBullet = {
  new_bullet_id: uuidv4(),
  new_bullet_title: content,
  new_bullet_note: "",
  save_location_url: hashtagUrl,
};

// you can also pick the direction
if (position === "top" || position === "bottom") {
  createNewBullet.position = position;
}

export const createBullet = async (bullet: CreateBullet, wfApiToken: string) => {
  try {
    const new_bullet = bullet;

    const response = await axios.post(CREATE_WF_BULLET_URL, new_bullet, {
      headers: {
        "Content-Type": "application/json",
        Authorization: `Bearer ${wfApiToken}`,
      },
    });

    return response.data;
  } catch (error) {
    logger.error("Error sending note to Workflowy:", error);
    throw error;
  }
};
```

A runnable, dependency-free version is in [`examples/create-bullet.mjs`](examples/create-bullet.mjs).

## 2. Operational guidance (learned from v0.1)

1. **Token handling.** Read the token from an environment variable or a secret manager. Never commit it, never log it, never put it in a URL. A Workflowy API key has full access to the account, so treat it like a password. Revoke it at the API key page if it leaks.
2. **Resolve the target once.** Each route (for example `#0`, `#1`, `#2`, inbox) maps to one target node. Look up each node's UUID once and store the mapping in config. Use the published API for that: authenticated `GET /api/v1/nodes-export` returns the whole outline with ids and parent ids. See the [official reference](https://workflowy.com/api-reference/). Note that the literal `today` in that API means the built-in calendar date node, not a node the user named "Today".
3. **Check before you write.** The create endpoint does not promise idempotency. Do not blindly retry a POST after a timeout: the first one may have landed. Before any retry, list the target's children (`GET /api/v1/nodes?parent_id=<id>`) and look for your text. A client-generated `new_bullet_id` helps you recognize your own write.
4. **Verify by read-back.** One to two minutes after a write, read the target's children and confirm the bullet exists with the exact text. If it does not, report it instead of silently re-posting.
5. **Add-only.** The capture path only creates bullets. It never edits, moves, completes or deletes existing nodes. Keep it that way in code, not only by convention.
6. **One writer at a time.** Serialize captures per target (queue or lock) so two writes cannot interleave.

## 3. Published alternative

Workflowy also publishes a documented REST API at [workflowy.com/api-reference](https://workflowy.com/api-reference/): `POST /api/v1/nodes` creates a node under a `parent_id` (a node id, a 12-character short id, a URL, or one of `inbox`, `today`, `tomorrow`, and so on). If you would rather not depend on the unpublished endpoint, build the same capture on that API. The guidance in section 2 applies unchanged.

## 4. Suggested shape

```text
chat message -> parse hashtag -> route table -> queue (per target)
             -> check children -> POST create -> read-back verify -> log
```

Keep the route table, the token and the node ids out of the repo. Keep the confirmation reply off by default; it can be offered after a number of successful captures.
